键盘问题的根因：原生在键盘弹起时把 WebView 整体压矮，键盘动画的每一帧都会让页面视口缩一次，居中的弹层跟着逐帧跳动、内容被压扁；原生其实把键盘高度推给了页面，但页面没有用。
修复思路：键盘动画期间把弹层尺寸锁在弹起前的大小（内容零重排）；键盘落定后，如果输入框被挡，先滚弹层内部，不够再整体上移；键盘收起后原位还原。

## 四、性能：回退已定位并修复

### 4.1 先说清楚：以前的数字为什么靠不住

- **测试机器是大小核混排的 CPU（i9-13900HX：8 个性能核 + 16 个能效核）**。以前没固定核心，同一个线程被排到能效核时能慢十倍以上，所以原版自己连跑两次能差 2–3 倍，版本之间的差异和噪声一样大。这次把整个测试进程**固定在同一组性能核**上，每个版本**完整跑两轮**。
- **旧日志里的时长单位标错了**：以前打印的「主线程任务 11.5ms」其实是 11.5 秒（脚本把秒当成了毫秒）。两边单位一样，所以大小关系没受影响，但绝对值全错了。已修正。
- 固定核心后两轮之间仍有 ±30% 左右的波动，所以下面**只把两轮方向一致、且远大于波动的差异当作结论**；长帧总数这类波动特别大的指标只用来看方向。

### 4.2 根因

都在视觉样式层第 1 段那条「给所有按钮统一加过渡」的规则里（`html:root body button`）。原版按钮只过渡位移 / 阴影 / 滤镜；优化版多加了背景色、边框色、文字颜色。定位办法是逐个属性做对照实验：

| 多加的东西 | 为什么慢 | 实测（降速 4 倍） |
| --- | --- | --- |
| **文字颜色（color）** | 它是可继承属性，过渡期间每一帧都要连带重算按钮里面的子元素 | 只给三个底部标签去掉它，快速切页多出来的样式重算就少了八成；只留它则和全加一样慢 |
| **换主题时所有按钮同时过渡背景色 / 边框色** | 一次换主题会改掉页面上每个按钮的配色，实测单帧有 **272 条**过渡在主线程同时跑（原版 33 条） | 换主题场景主线程比原版多 62%，超过 100ms 的帧从 8 / 1 个变成 33 / 31 个 |
| **边框色（border-color）** | 一条声明会拆成上下左右四条过渡；「按下后边框变色」的按钮（时间胶囊这类）每次开合都多跑几百毫秒 | 去掉后时间胶囊开合 8 次的主线程用时从 1.57 秒降到 1.06 秒（原版 0.74 秒） |

### 4.3 修复（只动 `patches/`，G:/About 工程未碰）

1. `ui-v2.css` 的全局按钮规则：过渡属性从「背景色、边框色、文字颜色、阴影、透明度、位移、滤镜」减为「**背景色、阴影、透明度、位移、滤镜**」。文字颜色、边框颜色改为即时切换——这本来就是原版的行为。
2. 换主题时全页过渡暂停两帧：`kb-stable.js` 监听根元素的主题属性，一变就挂两帧 `is-retheming` 标记；`ui-v2.css` 加一条规则，标记期间关掉所有过渡。这两帧里浏览器已经按新配色算过一遍样式，摘掉标记时数值不再变化，所以不会补跑过渡。连点换主题时标记会续上。

## 六、这份测试的局限（请一并考虑）

- 键盘是**页面级模拟**：每帧同时推送原生内边距并缩小视口，不是真机输入法。真机输入法自己的滚动行为、内边距是否逐帧到达，都没测。
- 性能数据来自桌面版无头浏览器（实际是 Edge 自带的 Chromium 内核，软件渲染）降速 4 倍，不等于手机 GPU；真机可能更轻也可能更重。
- **固定核心后两轮之间仍有 ±30% 左右的波动**，所以第四节只对「两轮方向一致、且远大于波动」的差异下结论。全程长帧总时长这类指标噪声很大（原版两轮是 37.0 秒和 9.1 秒），只作参考。
- 测试脚本自身修掉过 4 处误报（盲点到遮罩、文本域中心点落在键盘下、递归、变量名），以及这次修掉的 5 处工具问题（见 4.7）；上述结论都是修掉之后的数据。

### 7.2 换主题专项复核（17:00）

**目的**：验证「多次切换后浅色模式卡约半秒、无法继续切换」是否还存在，而不是只看浏览器数据。

**方法**：真机上用「原始截屏 + dd 取单像素」做低延迟采样（约 250–350ms 一次），采样点是设置面板底色（浅色 `241,241,241` / 深色 `30,32,39` / 马卡龙 `241,239,237`），并给每次点击打设备时间戳。这样测的是「像素真正变了」的时刻，不是 JS 自报的时刻。

**结果（1.0.68-ui2，即修复版）**：

| 场景 | 观测 |
|---|---|
| 单次点击「深色」 | 点击后 ≤190ms 内面板底色已变深（采样间隔 250ms 的下一个采样点即变色） |
| 8 次连点（总耗时 166ms） | 8 次全部生效；最后点「浅色」后 19ms 内的采样已是浅色 |
| 16 次连点（间隔 280ms，模拟手速） | 采样值随点击逐次翻转，没有出现任何一次「点了不变色」；结束后保持浅色 |
| 帧统计（gfxinfo framestats） | 连点期间 10 帧，JANKY 0，最长 16.9ms；logcat 无 `Skipped N frames` |
| 布局稳定性 | 浅色与马卡龙下主题按钮行位置完全相同（y 1448–1580），描述文字长短不会推走按钮 |
| 持久化 | 切深色后 `am force-stop` 再启动，主界面底色 `43,47,57`，主题保留 |

**结论**：当前装机版本上，「半秒无法切换」**没有复现**。连点、人手速度连点、冷启动后切换都正常，像素级延迟 ≤200ms。

**对照（同一脚本，4 倍降速的桌面 Chromium）**，用来解释这个问题当初是怎么来的：

| 指标 | 修复前规则（注入回旧样式） | 当前构建 |
|---|---|---|
| 点击瞬间并行过渡数 | **110 条** | 32 条 |
| 点击 → 主题属性变更 | 27–51ms | 19–28ms |
| 连点时最大帧间隔 | 70.5ms | 49.2ms |

也就是说：v2 层给所有按钮加的全局过渡里带了 `color`（可继承，换主题时每个按钮的子节点都要逐帧重算）和 `border-color`（展开成四条），一次换主题会在同一帧拉起上百条过渡；连点时每点一次就重来一遍，主线程在整段过渡窗口里被占住，手机上的感受就是「点了半秒没反应」。4.2/4.3 的修复（去掉这两个属性 + `is-retheming` 两帧内全关过渡）把这条链路拆掉了，上表与真机数据都支持这个结论。

**仍需你确认的**：手感本身（配色是不是「一下就切过去」、按钮按下反馈是否还在）。自动化只能证明时延和状态正确，好不好用还得你按一下。

### 7.3 深色模式下「浅色」预览按钮文字对比度（17:07 修复并装机）

**问题**：深色模式下，设置页「主题」行里白底的「浅色」预览块，文字几乎看不见。

**根因**：v2 层改写主题选择器时，把这一块的文字色从基线的固定值 `#4a5568` 换成了 `var(--text)`（`patches/ui-v2.css:245`），而它的底色仍硬编码 `#ffffff`。深色模式 `--text` = `#eef1f7`，于是变成近白字配白底。实测对比度 **1.13:1**（WCAG 正文要求 4.5:1），而基线原本是 7.5:1 —— 是这次改写引入的回归，不是设计意图。

**修法（只改样式，未动任何标记、时序与交互逻辑）**：

```css
/* 预览块的颜色代表「所代表主题」的配色，不能跟随当前主题 */
html:root body .themepick__btn[data-mode="light"] { background: #ffffff; color: #3a4356; }
@media (hover: hover) and (pointer: fine) {
  html:root body .themepick__btn[data-mode="light"]:hover { color: #2c3444; }
}
html:root body .themepick__btn[data-mode="light"]:active { color: #262d3b; }
html:root body .themepick__btn[data-mode="light"]:focus-visible { color: #2c3444; }
```

三态各钉一次的原因：全局按钮规则用 `filter: brightness()` 做悬停/按下反馈，白底已经到顶被钳制，字色却会跟着被提亮（悬停 1.05×、按下 0.94×），不单独钉住就会在悬停时反而变淡。

**验证**（`contrastcheck.mjs`：CDP 强制伪类读真实计算样式，并把 `brightness()` 滤镜计入 WCAG 比值）：

| 状态 | 修复前 | 修复后 |
|---|---|---|
| 深色 · 默认 | 1.13:1 | **9.92:1** |
| 深色 · 按下 | — | 12.59:1 |
| 深色 · 键盘聚焦 | — | 12.49:1 |
| 深色 · 悬停（桌面） | — | 11.98:1 |
| 浅色 / 马卡龙 · 默认 | 7.5:1 | 9.92:1 |

全部达到 AAA（≥7:1）。真机截图直接量：底色 `254,254,255` 对笔画核心 `58,65,80` = **10.15:1**（与浏览器一致）。另外两块按钮未受影响（深色 14.03:1、马卡龙 5.51:1）。

**布局与功能**：三块按钮矩形在三个主题下完全相同（117×46，left 16/141/267，top 422），字号 13px / 字重 600 未变；真机上浅色↔深色各切一次，面板底色 241 ↔ 30 正常翻转，无 JS 异常、无崩溃日志，待办 1 条 / 已办 10 条未变。

**装机**：新包 `TodayTodo-v1.0.68-ui3.apk`（versionCode 69 不变，便于回退），设备端 `base.apk` 与本地包同为 `824c688a…`，`firstInstallTime` 仍是 10-25（覆盖安装、数据保留），`lastUpdateTime 2026-11-27 17:04:12`。
